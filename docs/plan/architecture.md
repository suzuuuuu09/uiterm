## 技術スタック

[採用構成](../architecture.md#採用した製品構成) の詳細設計。採用判断は [ADR-0010](../adr/0010-evaluate-native-gpui-terminal.md)、現在の実装は [開発状況](../status.md) を参照する。

RustでUIとアプリケーションロジックを分離し、外部依存との境界をアダプターに集約する。GUI、CLI、設定から共通の操作APIを使う。

## ターミナル基盤

herdr-coreをPTY・プロセス・セッション管理の基盤として利用する。

- Unix Domain Socketを介して通信する。
- 公開されているJSON-RPC・バイナリプロトコルを利用する。
- herdr-coreへの依存を専用のアダプターに集約する。
- 使用するバージョンを固定する。
- セッションの実行状態はherdr-coreを正とする。
- GUIのレイアウトや表示状態はuiterm側で管理する。

## ターミナル描画

ネイティブ版libghostty-vtがVTを処理し、GPUIがセル、カーソルと選択範囲を描画する。出力とVT状態は端末単位で管理し、アプリケーションの状態管理から分離する。

- 日本語IME、文字幅、Nerd Fontの表示を維持する。
- 出力バッファと履歴に上限を設ける。既定のスクロールバックは2,000行とする。
- 不要な再描画と非表示ターミナルの負荷を抑える。

## UI

GPUIでWindow → Workspace → Tab → Paneを表示する。Workspaceはリポジトリや作業ディレクトリ、Tabは用途ごとの作業領域、Paneは分割した表示領域を表す。

## 状態管理

uitermはレイアウト、選択、表示状態と設定をRust側で管理する。セッションとエージェントの実行状態はherdr-coreと同期し、表示に必要な情報を保持する。状態を更新する操作は共通Action APIを通す。

## 操作API

Action Registryを実装し、アプリケーション内の操作を共通化する。以下のインターフェースから共通のアクションを呼び出す。

- GUI
- CLI
- キーバインド
- TypeScript設定
- イベントフック

アクションには型付きの引数と戻り値を定義する。アプリケーションの機能を個別のUIコンポーネントに閉じ込めず、再利用可能な操作として提供する。

## TypeScript設定

TypeScriptによるプログラマブルな設定を提供する。設定の実行には外部のNode.jsを利用し、アプリケーションには同梱しない。

- 型安全な設定API
- ヘルパー関数
- ユーザー定義関数
- 独自アクション
- イベントフック
- サイドバーのカスタマイズ

設定ファイルの実行環境とアプリケーションは分離し、JSON-RPCを介して通信する。設定ファイルに記述されたコードはユーザー権限で実行されるため、信頼できない設定ファイルを自動実行しない。設定の読み込みに失敗した場合も、アプリケーションを利用できるようにする。

## プロセス間通信

| 通信経路                | 方式                                    |
| ----------------------- | --------------------------------------- |
| Rust ↔ herdr-core       | 専用Unixソケット、JSON-RPC、Framed Mode |
| CLI ↔ uiterm            | Unixソケット（Phase 4）                 |
| 設定ランタイム ↔ uiterm | JSON-RPC over stdio                     |

端末出力はRust側でストリーム処理する。出力クレジット、再同期、ユーザー入力と自動応答の分離は [通信・操作契約](../interfaces.md#移行後も維持する条件) に従う。

## AIエージェント連携

herdr-core・OSC 7501・エージェント固有のHooksを利用する。

- 既存のCLIベースのエージェントを利用する。
- エージェントの状態取得と実行処理を分離する。
- 状態を共通の形式に変換する。
- サイドバーなどから状態を確認できるようにする。
- 特定のAIハーネスへの依存を避ける。

独自のAIハーネスは実装しない。将来的なAgentタブの実装ではACPや既存の公式APIを検討する。

## 国際化

初期対応言語は日本語・英語とする。表示文言は翻訳キーで管理し、日付、数値、相対時間は選択中のロケールで書式化する。Rust側の実装方式は移行時に決める。

- メニュー
- コンテキストメニュー
- サイドバー
- 設定画面
- 通知
- エラーメッセージ
- アクション名

UIに表示する文字列を直接ハードコードせず、翻訳リソースとして管理する。

## データ永続化

MVPではJSONによるファイル保存を採用する。

- ワークスペース構成
- タブ・ペイン構成
- ウィンドウ状態
- アプリケーションの内部設定

保存データにはスキーマバージョンを持たせる。ファイルの破損を防止するため、アトミックな書き込みを行う。ユーザー設定とアプリケーションが生成する状態データは分離する。

## 軽量性

- Chromiumを同梱しない。
- 不要なランタイムを同梱しない。
- ターミナルの出力履歴や通信バッファに上限を設ける。
- 非表示のUIによる不要な処理を抑える。
- 使用していない機能を常時実行しない。
- メモリ使用量・CPU使用率・ディスク容量・起動時間を計測する。
- アプリケーション本体だけでなく、関連プロセスや依存関係を含めて評価する。

## セキュリティ

- herdr-coreは専用ディレクトリ・ソケットで起動し、所有するプロセスだけを監視・終了する。
- IPCへのアクセスを制限し、端末入力、IME文字列、認証情報をログに残さない。
- 外部から受け取るデータを検証する。
- 信頼できないコードを自動実行しない。
- エージェントの既存設定を無断で変更しない。
- 将来的に外部Webページを表示する場合は、アプリケーションの特権APIから分離する。

## 開発環境

Nix FlakesでmacOS・NixOSの開発環境を再現する。RustはCargo、TypeScriptの依存管理はpnpmを使い、固定版とロックファイルの整合を保つ。Rustの整形・静的検査にはrustfmt・Clippyを使う。実行可能な開発・検証コマンドは [開発手順](../development.md) を参照する。

配布ビルドはcrane、CIはGitHub Actions、依存関係の更新はRenovateを利用する方針とする。
